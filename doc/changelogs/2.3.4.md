# ezoracle 2.3.4

Changes since 2.3.3. The trash table gets the columns of Exponential 6.0.15 that record who moved an object to the
trash and from where.

## Added

- Added: update/database/ezpublish/6.0/dbupdate-6.0.0-6.0.15-trash-columns.sql adds
  `ezcontentobject_trash.trashed_by` (INTEGER DEFAULT 0 NOT NULL) and `trashed_via` (VARCHAR2(100), nullable,
  because Oracle stores an empty string as NULL), each only when missing, so it can run again.

## Updated

- Updated: A fresh install creates `ezcontentobject_trash.trashed_via` without NOT NULL
  (settings/dbschema.ini.append.php, ColumnOptionTranslations), for the same reason.

## Upgrading from 2.3.3

- Run the update file once as the schema owner, then `php update/common/scripts/6.0/movetrashrecords.php` of the
  kernel copies what `<VarDir>/trash/trashed.json` recorded into the columns. Until the columns exist an
  Exponential 6.0.15 kernel works with the old table and keeps writing the file.
