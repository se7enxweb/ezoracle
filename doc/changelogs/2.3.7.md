# ezoracle 2.3.7

Changes since 2.3.6. Oracle 11g (11.2) and 12.1 work again: URL aliases resolve, and the DFS cluster backend lists
its files, on servers without the SQL of 12.1.

## Fixed

- Fixed (pull request #2): since 2.3.1 `eZOracleDB::md5()` returned `STANDARD_HASH()`, which Oracle has only from
  12.1 on, so every URL alias lookup (`eZURLAliasML`, `eZURLAliasQuery`) failed with ORA-00904 on 11g. Before 12.1
  the driver now hashes a string literal, which is all the kernel passes, in PHP, with the doubled quotes of
  `escapeString()` undone; that is the value `eZURLAliasML` stores in `text_md5`. Anything else is sent to an
  `md5_digest()` function, as before 2.3.1. From 12.1 on, and while the version cannot be read, nothing changes.
- Added: `sql/md5_digest_before_12.1.sql`, the `md5_digest()` of 2.3.0 (dbms_obfuscation_toolkit, which 21c
  removed) for SQL of your own on 11g; `sql/md5_digest.sql` needs 12.1 itself. INSTALL says which to use.
- Updated: `eZOracleDB::serverMajorVersion()` reads the major version once; `canAppendRowLimit()` uses it. An
  unreadable version (not connected yet) is not kept.

## Updated

- Updated: `connect()` forgets the server version and the database character set it read before, so a reconnect
  (a Velocity worker, a long CLI script) that reaches another server of the service reads both again instead of
  writing SQL for the old one.
- Updated: the literal check is `eZOracleDB::stringLiteralValue()` and the version test `hasStandardHash()`. Only a
  plain `'...'` literal is hashed in PHP: `N'...'` (national character set), `q'[...]'`, concatenations and
  unclosed literals go to `md5_digest()`. The pattern is possessive, so literals of any length are matched without
  backtracking.
- Fixed: the DFS cluster backend (`eZDFSFileHandlerOracleBackend::_getFileList()` with a limit) appended
  `OFFSET ... ROWS FETCH NEXT ... ROWS ONLY` on every release and failed with ORA-00933 before 12.1. It now reads
  the server version once per connection and uses ROWNUM before 12.1 and when the version is unknown
  (`limitQuery()`).
- Updated: new unit tests `tests/eZOracleBeforeRelease12Test.php` (no database needed): both MD5 paths with
  quotes, the empty string, umlauts, emoji, 200 000-character and 20 000-quote literals, non-literals, unknown
  versions, `canAppendRowLimit()` per release, and the cluster limit.
- Updated: README and INSTALL describe what works before 12.1.

## Notes

- On 12.1 and later Oracle refuses a string literal above 4000 bytes (ORA-01704), so `STANDARD_HASH()` of one
  fails; URL alias elements are far shorter. The PHP path before 12.1 has no such limit.
- Checked against Oracle AI Database 26ai Free (23.26) with the version forced to 11: the PHP hashes, a URL alias
  lookup through `eZURLAliasML::fetchByPath()`, offset/limit queries and the ROWNUM file list return the same
  results as the 12.1 path. No 11g server was available for this release; the contributor's report covers 11g XE
  11.2.0.2.

## Upgrading from 2.3.6

- Nothing to run. On 11g, create `md5_digest()` from `sql/md5_digest_before_12.1.sql` only if SQL of your own calls
  it.
