# ezoracle 2.3.6

Changes since 2.3.5. Long multibyte texts load into CLOB columns, and the tables of cjw_newsletter and syndication
whose columns are named `comment` and `mode` work on Oracle.

## Updated

- Updated: the schema handler's data loading (`eZOracleSchema::generateTableInsertSQLList()`) failed with ORA-22921
  on every CLOB value above 4000 bytes that held multibyte characters (German umlauts, Chinese, emoji): it cut and
  counted the value in bytes, while Oracle counts a CLOB in characters. The value is now cut at UTF-8 character
  boundaries into literals of at most 4000 bytes and appended with `DBMS_LOB.APPEND( TO_CLOB(...) )`, which needs
  no length. A NULL value in such a row stays NULL.
- Updated: that PL/SQL block ran a `COMMIT` of its own, so a failing row later in the same data set left the rows
  before it behind although `insertSchema()` rolls the data set back. The block has no `COMMIT` any more; the
  caller's transaction decides.
- Updated: columns named by Oracle reserved words. The schema handler quotes every reserved word, in upper case,
  wherever it names a column (CREATE TABLE, ALTER TABLE, indexes, the auto_increment trigger, the data INSERTs), so
  `cjwnl_approval.comment`, `cjwnl_schedule.mode` (cjw_newsletter) and `ezsyndication_import.comment` (syndication)
  can be created (ORA-03050 before). Reading the schema back still gives the lower-case names.
- Updated: the driver quotes the column names of the new setting `ezoracle.ini [QuotedIdentifierSettings]
  ColumnNames[]` (default `comment`, `mode`) in every statement it runs, so `SELECT comment FROM cjwnl_approval` and
  the extensions' persistent objects work unchanged (ORA-00936 before), and nothing changes for MySQL, PostgreSQL or
  SQLite. String literals, quoted names, comments, bind variables, longer names (`comment_id`), `LOCK TABLE ... IN
  EXCLUSIVE MODE` and `COMMENT ON` statements are left alone.
- Updated: a bind variable named after a field that is a reserved word (`:Comment`, used for texts above 2000
  characters) failed with ORA-01745; such a placeholder now gets a prefix (`:ezb_Comment0`).
- Updated: new unit tests `tests/eZOracleClobAndReservedWordsTest.php` (no database needed).

## Notes

- `comment` is a CLOB in both extensions' schemas. Oracle cannot compare or sort a CLOB with `=` or `ORDER BY`
  (ORA-22848); `LIKE` works. Neither extension does either in SQL (the syndication list filters and sorts in PHP).
- A further reserved-word column name in an extension only needs to be added to `ColumnNames[]`; the schema handler
  already creates it quoted.

## Upgrading from 2.3.5

- Nothing to run. Tables that failed to be created before (cjw_newsletter, syndication) can now be installed.
