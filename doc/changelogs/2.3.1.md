# ezoracle 2.3.1

Changes since 2.3.0. This release makes the driver work on PHP 8.0 to 8.5 with
Exponential 6.0.15 and Oracle 19c to 26ai, and adds the connection, tracing and
maintenance features listed below. Tested against Oracle AI Database 26ai Free
(23.26) with PHP 8.5 and oci8 3.4.1: a full kickstarter installation of the
sevenx_multisite package, its front page and admin, and the driver's own probes.

## Added

- Added: lock(), unlock() and databaseClientVersion() in the Oracle driver
- Added: Optional case-insensitive comparison and sorting on Oracle (site.ini `OracleCaseInsensitive`, `OracleCaseInsensitiveSort`)
- Added: Connection resilience, tracing and slow query log settings for the Oracle driver (settings/ezoracle.ini)
- Added: Oracle maintenance commands for the console: ext:ezoracle:health, gather-stats, recompile, purge-recyclebin, sequence-sync, schema-diff, indexes, report, datapump, ci-indexes
- Added: Cronjobs for Oracle statistics, health (with mail), recycle bin and sequences (cronjob parts ezoracle, ezoraclehealth)
- Added: ezinfo.php

## Updated

- Updated: The database applies arrayQuery()'s limit and offset (OFFSET / FETCH)
- Updated: schema() reads the columns and indexes of all tables with one query each
- Updated: removeRelation() drops tables without keeping them in the recycle bin
- Updated: ora-update-seqs.php uses the oci_* functions and can take the password from the environment
- Updated: ora-grant.php can take the new password from the environment and grants CREATE VIEW
- Updated: The cluster example in file.ini describes the DFS setup this kernel has
- Updated: Package metadata names the license, the repository and Exponential
- Updated: INSTALL says the md5_digest and bitor functions are optional
- Updated: The driver returns Oracle's NULL for text columns unless '' mapping is enabled
- Updated: README and INSTALL describe the Exponential installation, every setting, the commands and the cronjobs
- Updated: Version 2.3.1

## Fixed

- Fixed: The Oracle driver and schema handler use __construct() so they connect on PHP 8
- Fixed: The Oracle driver's error paths give no PHP 8 warnings, notices or type errors
- Fixed: Inserting a schema with an empty table no longer stops with a TypeError
- Fixed: MySQL column types map to valid Oracle types in the schema handler
- Fixed: md5() and bitOr() work without functions in the schema
- Fixed: A table dropped without its sequence can be created again
- Fixed: Text columns accept the empty string on Oracle
- Fixed: Index names are unique in the Oracle schema and generated the same way every time
- Fixed: The Oracle driver talks UTF-8 by default and reports Unicode support to the setup
- Fixed: Text columns read back the empty string instead of NULL (now optional, see Updated)
- Fixed: Reading a schema back from Oracle reports no default where there is none
- Fixed: Reading a schema back gives VARCHAR2 lengths in characters
- Fixed: Auto-increment columns of extension tables are recognised when a schema is read back
- Fixed: The Oracle reserved word list can match a name
- Fixed: Reading a schema back leaves out function-based indexes
- Fixed: The MySQL to Oracle conversion scripts run on PHP 7 and 8
- Fixed: The Oracle DFS cluster backend answers every call of the kernel's DFS handler
- Fixed: The Oracle cluster gateways bind the file hash as a variable and report the right error

## Removed

- Nothing was removed. The old md5_digest and bitor SQL functions are no longer
  needed by the driver (sql/md5_digest.sql is rewritten on STANDARD_HASH for
  SQL of your own that still calls it).

## Upgrading from 2.3.0

- Requirements: PHP 8.0 or later with oci8 3.x, Oracle 12.1 or later (19c or
  later supported), Exponential 6.0.15 for the Oracle choice in the installers.
- New schemas: text columns are created nullable (Oracle stores '' as NULL),
  VARCHAR2 lengths count characters (the driver sets NLS_LENGTH_SEMANTICS=CHAR),
  index names that repeat across tables are prefixed with their table, and
  names over 30 bytes get a stable hash suffix instead of a counter. Existing
  schemas keep working; the schema checker (ext:ezoracle:schema-diff) shows
  where an old schema differs from the new form.
- The md5_digest() and bitor() functions are no longer used by the driver.
- New settings, all off or keeping the old behaviour by default:
  - site.ini [DatabaseSettings] `OracleEmptyStringForNull=disabled` (NULL as
    Oracle stores it), `OracleCaseInsensitive=disabled`,
    `OracleCaseInsensitiveSort=BINARY_CI`
  - ezoracle.ini [ConnectionSettings] `Persistent=inherit`, `DRCP=disabled`,
    `ConnectionClass=`, `ConnectString=`, `TnsAdmin=`, `Hosts[]`, `ServiceName=`,
    `Failover=enabled`, `LoadBalance=disabled`, `ConnectTimeout=0`, `Edition=`,
    `RetryCount` (site.ini ConnectRetries when unset), `RetryDelay`,
    `RetryBackoff=2`, `ReconnectErrors[]`, `RetryReads=enabled`,
    `CallTimeout=0`, `KeepAliveInterval=0`
  - [PerformanceSettings] `Prefetch=0`, `LobPrefetch=0` (php.ini defaults)
  - [TraceSettings] `ClientIdentifier=`, `ModuleName=`, `Action=`, `ClientInfo=` (not set)
  - [LogSettings] `SlowQueryThreshold=0` (off), `SlowQueryLog=oracle-slow.log`,
    `MaskLiterals=enabled`, `StatementCounts=disabled`
  - [CaseInsensitiveSettings] `Columns[]`, [HealthSettings], [StatisticsSettings],
    [DataPumpSettings] `Directory=DATA_PUMP_DIR`
  - [CronjobSettings] `GatherStatistics`, `HealthMonitor`, `PurgeRecycleBin`,
    `SequenceCheck`, `SequenceFix` all `disabled`, `HealthMailReceivers[]` empty
- After updating, regenerate the autoloads (php bin/php/ezpgenerateautoloads.php -e)
  for the new class eZOracleTools, and clear the INI cache.
