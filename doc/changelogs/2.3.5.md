# ezoracle 2.3.5

Changes since 2.3.4. The trash table gets the index of Exponential 6.0.15 on the user who moved an item to the trash.

## Updated

- Updated: update/database/ezpublish/6.0/dbupdate-6.0.0-6.0.15-trash-columns.sql also creates the index
  `ezcobj_trash_trashed_by` on `ezcontentobject_trash.trashed_by`, which the kernel's `share/db_schema.dba` declares
  from 6.0.15 on: the trash view counts the items per user and filters by user. It is created only when no index of
  the table starts with `trashed_by` yet, so the file can still run again. A fresh install gets the index from the
  kernel's schema.

## Upgrading from 2.3.4

- Run the update file again as the schema owner: the columns are already there and are left alone, the index is
  added.
